현재 운영 GitHub 커밋·Sheets 상태를 이 패키지 제작자가 직접 조회한 것은 아닙니다.
사용자의 v3.7.10 운영 확인을 바탕으로 제공된 정상 v3.7.10 소스를 기준으로 만들었습니다.

현재 저장소의 전체 ZIP을 내려받고, 이번 패치 압축을 푼 폴더에서 다음 읽기 전용 검사를 실행합니다.

    python CHECK_3712.py 현재_저장소_전체소스.zip

PASS_BASE: 확인된 기준과 일치합니다.
ALREADY_COMPLETE: 이번 v3.7.12와 일치하므로 중복 적용할 필요가 없습니다.
STOP: 기준 소스와 다릅니다. 임의 덮어쓰기를 중단합니다. v3.7.5 누락이 확인되면 앞서 제공한
R16 안전복구 검사·패치를 먼저 적용하여 정상 v3.7.10 기준으로 맞춰야 합니다.
검사 프로그램은 서버 접속·파일 변경·설치·배포·동기화를 전혀 하지 않습니다.

원본 저장소와 운영 Sheets의 사본을 배포 전에 보관하세요.
교사 앱에는 기존 카탈로그 자동 동기화가 있어 로그인된 교사 화면을 다시 열 때도
Courses/Exams/Questions가 변경될 수 있습니다. 수동 버튼을 누르기 전이라고 안전한 것이 아닙니다.
Exams/Questions/QuestionOverrides/Reports에서 아래 ID의 기존 등록·교사 수정본 충돌을 확인하세요.

- physics2-advanced-r05

## 정적 사이트 적용

ZIP 파일 자체를 저장소에 올리는 것이 아닙니다. ZIP 안 파일들을 기존 경로에 맞게 추가·덮어씁니다.
이번 패치는 삭제 지시가 없습니다. 정상 기준에서 전체 GitHub 소스를 새로 지울 필요도 없습니다.
기존 pages.yml, runtime-config.js, share-config.js, Apps Script, Worker는 패치에서 제외했습니다.
저장소 변수 YP_API_URL, 교사 PIN, Script Properties의 비밀값, 학생 토큰은 바꾸지 마세요.

로컬 Node.js 환경에서 npm test 후 기존 GitHub Pages 배포 절차를 사용합니다.
배포 후 Ctrl+F5로 새로고침하고 교사 화면에서 자동 시험 설정 동기화 결과를 확인하세요.
실패했을 때만 연결 상태·권한·QuestionOverrides 충돌을 먼저 확인한 후 기존 수동 동기화를 사용합니다.
Apps Script와 Cloudflare Worker 재배포, 설치 함수 실행, PIN 재설정은 필요하지 않습니다.

## 등록 내용

일반 물리2 → 전자기·파동 총괄평가:
객관식 20+서술형 5, 모두4점, 100점. 1~20번은 학생 선택번호1~5, 21~25번은 실제 점수0~4입니다.
빈칸은 미채점입니다. 서술형의 숫자1은 실제1점이며 주간테스트의 만점기호1과 다릅니다.
11~15회 복습 결과를 기존 누적 분석에 연결하며, 학부모 총괄평가 별도 영역과 성적표 버튼을 사용합니다.
제공 문제지17쪽·해설지26쪽 원본 PDF, 문제페이지17PNG와25해설이미지가 포함되어 있습니다.
원문과 다른 해설 문구는 SOURCE_REVIEW_3712.md에 분리했습니다. 공식 정답은 임의 변경하지 않았습니다.

물리2심화 → 5회차:
원본 최종 문제7개, 배점15·15·15·15·15·15·10점,100점입니다.
4번 거친 구간+원형 궤도,6번 공과 상자 충돌,7번 움직이는 빗면 버전입니다.
문제지와 해답지6번 배점 차이는 문제지15점(10+5)을 따릅니다. 이전 재구성 그림은 포함하지 않습니다.

모든 이전 시험·학생 기록·영구 링크를 다른 버전으로 변환하거나 재채점하지 않습니다.
기존 물리1 16회차6문항 성적은 구형으로 남고, 새 입력은개정7문항입니다.
물리2심화4회차도 기존/개정 구분을 유지합니다.

## 배포 후 확인

교사 입력란25개와 총점100점, 객관/서술 입력 구분을 확인합니다.
새 성적 저장 후 같은 학생의 기존 기록·영구 링크를 확인합니다.
학부모 통합 포털에서 총괄평가 별도 카드와 성적표 바로 보기를 확인합니다.
원문 문제와원문 해설그림, 제출 전 해설숨김, 제출 후원문/동형 재도전 및 Word/PDF출력을 확인합니다.
이는 운영 배포 후의 확인 사항입니다. 로컬검증을 운영 서버의 실시간 검증으로 간주하지 마세요.
