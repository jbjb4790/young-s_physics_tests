## 2. 입력·점수 계산 검증

- 총괄 객관식 1~20번은 `binary` 모드입니다.
  - `0` → 0점
  - `1` → 4점
  - 그 밖의 값 → 저장 차단
- 총괄 서술형 21~25번은 `points` 모드입니다.
  - `0~4`의 실제 점수를 그대로 사용
  - 서술형의 `1`은 실제 1점이며 만점 기호가 아님
  - 4점 초과, 음수, 잘못된 문자열 차단
- 기존 주간 복습의 `0`, `1=문항 만점`, `P1=정확히 1점`, 일반 부분점수 규칙은 그대로 유지됩니다.
- 탭 붙여넣기에서 빈 셀 위치가 보존됩니다.
- 같은 과정·학교·학생 이름의 지정된 복습 회차만 총괄 리포트에 연결됩니다.
- 공백, 영문 대소문자, 괄호·하이픈·밑줄 차이는 학생 연결키 정규화에서 흡수됩니다.
- 누적 복습 성취율은 단순 회차 평균이 아니라 각 회차 만점으로 가중 계산됩니다.

## 4. 오답 재도전·동형 문제 공개 순서

학생 리포트에서 다음 공개 순서를 자동 테스트했습니다.

```text
원문 문제 표시
→ 학생이 원문 답 제출
→ 검수된 정답·해설·공식·실수·루브릭 공개
→ 동형 문제 활성화
→ 학생이 동형 답 제출
→ 동형 정답·전체 해설 공개
```

- 원문 제출 전 정답·해설은 `hidden` 상태입니다.
- 원문 제출 전 동형 문제는 `locked` 상태입니다.
- 확인 필요 상태의 문항은 정답 자동 공개가 차단됩니다.

## 7. 학생 링크·Google Sheets 서버 로직 검증

자동 테스트로 다음을 확인했습니다.

- 학생 연결키는 `과정 + 정규화한 학교 + 정규화한 이름`의 SHA-256 값입니다.
- 학생 결과 링크는 서버 토큰, HMAC 지문, 학생 식별 다이제스트를 함께 검증합니다.
- 기존 시트는 열 번호가 아니라 기존 헤더 이름으로 새 17열 Reports 스키마에 재배치됩니다.
- 총괄 점수 파서는 `binary`와 `points`를 구분합니다.
- 총괄 리포트 조회 응답에는 지정 복습 회차의 `historyRecords`가 포함됩니다.
- 동일 학생 수정 시 기존 서버 토큰을 유지하는 구조가 보존됩니다.

## 10. 실제 배포 후 확인이 필요한 항목

실제 Google Spreadsheet ID, 운영용 Apps Script `/exec` URL, `WRITE_KEY`, `FINGERPRINT_SECRET`은 제공되지 않았으므로 다음 항목은 운영 계정에 배포한 뒤 최종 확인해야 합니다.

- 컴퓨터 A 저장 → Google Sheets 행 생성 → 컴퓨터 B 새로고침 동기화
- 실제 웹 앱 권한 정책에서 학부모 링크 접근
- Apps Script 새 버전 배포 후 `ping`
- 운영 도메인의 클립보드 권한
- 실데이터 행 변조 후 `checkIntegrity` 탐지

코드·데이터·브라우저 데모 수준의 검증은 모두 통과했지만, 위 항목은 실제 Google 계정 자격정보 없이는 실서버 저장을 검증할 수 없습니다.
