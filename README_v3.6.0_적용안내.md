# Young’s Physics v3.6.0 적용 안내

## 이번 버전의 핵심 변경

1. 학부모용 학생 통합 페이지에서 **누적 가중 성취율 숫자를 노출하지 않습니다.**
2. 교사용 홈페이지에서 선생님이 직접 **반을 만들고 학생을 반별로 묶을 수 있습니다.**
3. 반에서 학생 이름을 클릭하면 학생 정보가 자동으로 채워지고 바로 시험 결과를 입력할 수 있습니다.
4. 선택한 학생의 기존 시험 결과를 같은 화면에서 **수정·삭제**할 수 있습니다.
5. 같은 학생이 같은 시험을 다시 저장하면 신규 중복 성적을 만들지 않고 **기존 성적을 자동 수정**합니다.
6. 반을 삭제하거나 학생을 반에서 제외해도 학생 프로필·기존 시험 성적·학부모 영구 링크는 삭제되지 않습니다.

---

## 0. 적용 전 백업

### Google Sheets
운영 Spreadsheet에서 `파일 → 사본 만들기`로 전체 백업을 먼저 만듭니다.

### Apps Script
현재 `Code.gs` 내용을 별도 텍스트 파일에 복사해 둡니다.

### GitHub
현재 정상 배포 중인 저장소를 ZIP으로 내려받거나 별도 브랜치를 만들어 둡니다.

---

## 1. Apps Script 적용

운영 Spreadsheet에서:

`확장 프로그램 → Apps Script → Code.gs`

1. 기존 `Code.gs` 전체를 삭제합니다.
2. `YoungsPhysics_반별학생_성적관리_v3.6.0_Code.gs` 전체 내용을 붙여넣습니다.
3. 저장합니다.

이번 버전은 기존 OAuth 권한을 그대로 사용하므로 현재 `appsscript.json`이 정상이라면 변경하지 않아도 됩니다.

### 실행하지 않아도 되는 함수
기존 v3.5.x 운영본에서 업데이트하는 경우 아래 함수는 다시 실행하지 않습니다.

- `installYoungsPhysics()`
- `resetTeacherPin()`
- `repairReportStorage()`
- `migrateStudentPortals()`

`Classes`와 `ClassMembers` 시트는 반별 학생 기능을 처음 사용할 때 자동 생성됩니다.

---

## 2. Apps Script 새 버전 재배포

`배포 → 배포 관리 → 기존 웹 앱 편집 → 버전: 새 버전 → 배포`

기존 설정을 유지합니다.

- 실행 사용자: 나
- 액세스 권한: 로그인하지 않은 사용자를 포함한 모든 사용자

기존 배포를 새 버전으로 갱신하면 보통 `/exec` 주소는 유지됩니다. 주소가 유지되었다면 GitHub의 Apps Script URL 설정도 바꿀 필요가 없습니다.

기능 버전은 v3.6.0이지만 통신 호환을 위해 `?action=ping`의 API 식별자는 기존 `3.3.0-hosted-parent-bridge`를 유지합니다.

---

## 3. GitHub 패치 적용

`YoungsPhysics_반별학생_성적관리_v3.6.0_GitHub패치.zip`을 컴퓨터에서 압축 해제합니다.

압축 내부의 파일과 폴더를 **GitHub 저장소 최상위에 경로 그대로 덮어씁니다.** ZIP 파일 자체를 저장소에 올리면 안 됩니다.

### 중요: 패치가 건드리지 않는 파일
권장 GitHub 패치에는 아래 두 파일을 넣지 않았습니다.

- `.github/workflows/pages.yml`
- `site/assets/runtime-config.js`

따라서 현재 정상화된 GitHub Pages workflow와 Apps Script `/exec` 연결값을 덮어쓰지 않습니다.

권장 커밋 메시지:

`Add class roster quick entry and editable assessment records v3.6.0`

커밋 후 현재 사용 중인 GitHub Pages Actions가 성공하는지 확인합니다.

배포가 끝나면 브라우저에서 강력 새로고침합니다.

- Windows: `Ctrl + Shift + R`
- Mac: `Command + Shift + R`

---

## 4. 새 반 만들기

교사 인증 후 홈페이지에서 `반별 학생` 영역을 사용합니다.

1. `+ 반 추가` 클릭
2. 반 이름 입력
   - 예: `물리1 월 5시반`
   - 예: `물리1 심화 토요반`
3. 반 탭이 생성됩니다.

반은 과정·시험과 별개인 **선생님 관리용 묶음**입니다. 같은 학생을 여러 반에 배정할 수도 있습니다.

---

## 5. 반에 학생 추가

### 신규 학생

1. 원하는 반 탭 선택
2. `+ 새 학생 추가`
3. 학생 이름 입력
4. 학교·학년·학교 반/번호는 필요한 경우 입력
5. 저장

학교를 비워 두면 기존 정책대로 `미기입`으로 저장됩니다.

### 기존 학생을 반에 넣기

1. 반 탭 선택
2. `기존 학생 배정`
3. 기존 학생 선택
4. 배정

학생의 과거 시험 성적이나 영구 학부모 링크는 그대로 유지됩니다.

---

## 6. 학생 이름 클릭 후 바로 시험 입력

반 화면에서 학생 이름 카드를 클릭하면 다음 정보가 자동으로 입력 화면에 연결됩니다.

- 학생 이름
- 학교
- 학년
- 반·번호
- StudentId

그 상태에서 과정과 시험을 선택하고 문항별 결과를 입력한 뒤 저장합니다.

학생을 다른 학생으로 바꿀 때 이전 학생에게 입력하던 문항 값이 남아 있으면 확인 창을 띄우고, 전환 시 문항 입력값을 초기화해 서로 다른 학생의 답안이 섞이지 않도록 했습니다.

### 같은 학생의 같은 시험을 다시 입력하는 경우

학생 카드로 학생을 선택한 상태에서 이미 존재하는 같은 시험을 다시 저장하면 **신규 행을 만들지 않고 기존 성적 기록을 자동 수정**합니다. 학생 영구 링크도 그대로 유지됩니다.

---

## 7. 학생 시험 결과 수정

학생을 클릭하면 입력 폼 상단에 `기존 시험 결과`가 표시됩니다.

해당 시험 옆의 `수정`을 누르면 기존 점수가 입력 화면으로 불러와집니다. 수정 후 저장하면:

- 기존 Report 토큰 유지
- 학생 영구 링크 유지
- 기존 시험별 링크 유지
- 점수·문항별 결과·UpdatedAt만 갱신

됩니다.

---

## 8. 학생 시험 결과 삭제

학생의 기존 시험 결과에서 `삭제`를 누르면 확인 창이 나타납니다.

삭제를 확정하면 해당 시험 결과 행만 `Reports`에서 삭제됩니다.

삭제하지 않는 데이터:

- 학생 프로필
- 학생 영구 학부모 링크
- 다른 시험 성적
- 반 배정

삭제 후 학부모 통합 페이지의 시험 수·평균·강점·약점·성취 추이는 다음 조회부터 남은 기록 기준으로 다시 계산됩니다.

---

## 9. 반에서 학생 제외 / 반 삭제

### 학생을 반에서 제외
`현재 반에서 제외`를 누르면 해당 반과의 연결만 해제됩니다.

### 반 삭제
반 삭제는 반과 반 배정만 비활성화합니다.

학생 프로필과 성적을 삭제하지 않으며, 다른 반에도 속하지 않은 학생은 `미분류`에서 다시 확인할 수 있습니다.

---

## 10. 학부모용 학생 통합 페이지 변경

학부모 페이지에서 `누적 가중 성취율 XX%` 숫자는 더 이상 표시하지 않습니다.

대신 다음은 계속 제공합니다.

- 누적 시험 수
- 주간 복습 시험 수
- 총괄평가 수
- 시험 평균 성취율
- 최근 시험 성취율
- 성취 추이
- 강점·보완 단원
- 전체 오답/부분점수 학습
- 시험별 상세 결과

서버가 반환하는 공개 학생 포털 누적 객체에서도 `weightedPercent`, `totalScore`, `totalMaxScore` 필드를 제거했습니다.

### ClassMembers

## 12. 업데이트 후 빠른 확인

1. 교사 인증 성공
2. `+ 반 추가`로 테스트 반 생성
3. 기존 학생 한 명을 반에 배정
4. 학생 이름 클릭
5. 기존 시험 결과가 보이는지 확인
6. 기존 성적 한 건 `수정` 후 저장
7. 같은 시험이 중복 생성되지 않았는지 확인
8. 테스트용 결과 한 건 삭제 후 학생 영구 페이지에서 사라지는지 확인
9. 학부모 페이지 첫 화면에 `누적 가중 성취율` 숫자가 없는지 확인
10. 다른 컴퓨터에서 같은 반·학생 목록이 보이는지 확인

## 13. GitHub 전체 프로젝트 ZIP을 사용할 때

`전체프로젝트.zip`에는 v3.6.0용 안전한 Pages workflow도 포함되어 있습니다. 신규 저장소를 만드는 경우 사용할 수 있습니다.

이미 운영 중인 저장소라면 **전체 ZIP보다 권장 GitHub 패치 ZIP을 사용하는 편이 안전**합니다. 현재 동작 중인 `pages.yml`과 `runtime-config.js`를 보존할 수 있기 때문입니다.
