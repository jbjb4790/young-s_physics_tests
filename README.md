# Young’s Physics 복습 테스트·총괄평가 통합 성적 분석 시스템

GitHub Pages 정적 사이트와 Google Sheets + Apps Script를 연결하여 주간 복습 테스트와 파트 종료 총괄평가를 같은 학생 기준으로 분석하는 시스템입니다.


## 2.1 로고 기반 리브랜딩

사용자가 제공한 공식 **Young’s Physics 원자 로고**를 교사용 사이트, 학생·학부모 리포트, 설치 안내 화면, 실제 DOCX 출력에 공통 적용했습니다.

- 로고의 남색·선명한 파란색·흰색을 중심으로 전체 색상 체계 통일
- 교사용 첫 화면에 과학 학습 관리형 히어로, 시험·학생 입력 카드, 실시간 점수 링, 한 번 저장 패널 적용
- 학생 리포트에 브랜드 표지, 총괄 점수 패널, 평균 비교, 강점·보완 카드, 단원별 레이더 차트, 문항 분석, 오답 재도전 영역 적용
- 모바일에서 카드·표·그래프가 화면 밖으로 밀리지 않도록 반응형 레이아웃 보강
- Word 출력에도 동일 로고와 색상 체계를 적용하고 로고·그래프·문제 이미지를 문서 내부에 삽입
- 총괄평가·복습 기록 연결, 점수 계산, Google Sheets 저장, 학생 토큰·지문 검증 등 기존 기능과 데이터 구조는 그대로 유지

디자인만 기존 통합판 2.0에 적용하는 경우에는 웹 파일만 덮어쓴 뒤 **GitHub Pages를 다시 배포**하면 됩니다. `Code.gs`와 Google Sheets 스키마는 이번 리브랜딩에서 바뀌지 않았으므로 Apps Script 재배포와 시험 설정 재동기화는 필요하지 않습니다.

## 이번 확장 범위

- 물리1 역학 총괄평가: 25문항, 100점, 등록 완료
- 물리1 전자기·파동 총괄평가: 25문항, 100점, 등록 완료
- 물리2 역학 총괄평가: 연결 정책 등록, 문제 자료 대기
- 물리2 전자기·파동 총괄평가: 연결 정책 등록, 문제 자료 대기
- 물리1심화 총괄평가: 연결 정책 등록, 문제 자료 대기

총괄평가 입력 규칙은 객관식 1~20번의 정오표 `0/1`과 서술형 21~25번의 실제 점수 `0~4`입니다. 총괄평가에서 서술형 `1`은 기존 주간 복습 입력 규칙의 “정답·만점”이 아니라 실제 1점입니다.

## 복습 기록 연결 범위

| 총괄평가 | 자동 연결하는 주간 복습 기록 |
|---|---|
| 물리1 역학 | 물리1 2~8회 |
| 물리1 전자기·파동 | 물리1 10~16회 |
| 물리2 역학 | 물리2 2~9회 |
| 물리2 전자기·파동 | 물리2 11~15회 |
| 물리1심화 | 물리1심화 2~7회 |

연결키는 `과정 + 정규화된 학교 + 정규화된 학생 이름`입니다. 총괄평가는 학교를 필수로 입력하도록 하여 동명이인 및 다른 학교 기록이 섞이지 않게 했습니다.

## 핵심 기능

- 총괄 객관식 O/X 버튼과 정오표 붙여넣기
- 총괄 서술형 0~4점 입력과 빠른 점수 버튼
- 기존 주간 복습의 `0`, `1`, `P1`, 일반 부분점수 규칙 유지
- 한 버튼으로 Google Sheets 저장, 통계 재계산, 복습 기록 연결, 결과 링크 생성·복사
- 동일 총괄평가 응시자 평균·문항별 평균·단원별 평균
- 학생의 주간 복습 누적 성취율, 회차별 흐름, 누적 강점·보완 영역
- 총괄평가의 오답·부분점수 원문 재도전
- 원문 답 제출 전 정답·해설 비공개
- 원문 제출 후 새 동형 문제 활성화, 동형 답 제출 후 정답·해설 공개
- 서버 토큰, HMAC 지문, 학생 식별 다이제스트 검증
- 실제 OOXML `.docx` 생성, 로고·그래프·문제 이미지 내부 삽입
- A4 PDF·인쇄

## 운영 회차

주간 복습은 총 34개입니다.

- 물리1: 2~8회, 10~16회
- 물리1심화: 2~7회
- 물리2: 1~9회, 11~15회

물리1 1회는 복습 테스트가 없어 제외하며, 물리1 9회와 물리2 10회도 현재 제외 상태입니다. 총괄평가 5개를 포함하면 카탈로그에는 총 39개 시험이 있습니다.

## 빠른 설치

상세 절차는 `INSTALL_KO.md`를 따릅니다.

### 기존 통합판 2.0에 디자인만 적용

1. 운영 저장소를 백업합니다.
2. 리브랜딩 패치 ZIP의 `site/` 파일을 기존 저장소에 덮어씁니다.
3. GitHub Pages를 다시 배포하고 데스크톱·모바일 화면을 확인합니다.
4. 이번 패치만 적용할 때는 `Code.gs` 교체, Apps Script 재배포, 시험 설정 서버 동기화가 필요하지 않습니다.

### 신규 설치 또는 총괄평가 통합 기능까지 함께 설치

1. 기존 운영 Sheet를 백업합니다.
2. `apps-script/Code.gs`를 기존 Apps Script에 교체합니다.
3. Script Properties의 `SPREADSHEET_ID`, `WRITE_KEY`, `FINGERPRINT_SECRET`을 확인합니다.
4. `connectThisSpreadsheet()`를 실행합니다. 기존 헤더 이름을 기준으로 새 스키마에 안전하게 재배치됩니다.
5. Apps Script를 새 버전으로 재배포합니다.
6. GitHub Pages 파일을 교체합니다.
7. 교사용 화면에서 서버 설정 후 `시험 설정 서버 동기화`를 실행합니다.
8. 기존 학생 한 명의 복습 기록과 총괄 기록을 같은 학교·이름으로 저장해 통합 연결을 확인합니다.

## 기존 Google Sheet 마이그레이션

이번 버전은 Exams, Questions, Reports 시트에 새 열이 추가됩니다. `initializeSheets_()`는 기존 1행 헤더의 이름을 읽고 데이터를 새 열 순서로 재배치하므로, 열 위치 변경으로 기존 기록이 밀리는 문제를 방지합니다. 그래도 운영 데이터에는 항상 사전 백업이 필요합니다.

기존 Reports의 `StudentKey`가 빈 경우에도 조회 시 자동 계산하여 연결할 수 있습니다. 무결성 검사를 완전히 갱신하려면 WRITE_KEY와 FINGERPRINT_SECRET 설정 후 교사용 API의 `repairIntegrity`를 실행합니다.

## 자동 테스트

```bash

```

총 50개 자동 테스트가 카탈로그, 점수 파서, 연결 범위, 학생 분리, 문항 데이터, 검수 교정, 이미지 범위, Apps Script 스키마, 토큰·지문 검증, 실제 OOXML DOCX 생성까지 확인합니다.

## 보안 원칙

- 실제 학생 이름·학교·점수·토큰을 GitHub에 커밋하지 않습니다.
- `WRITE_KEY`와 `FINGERPRINT_SECRET`은 Apps Script Properties와 교사 브라우저에만 둡니다.
- Google Sheets를 원본 저장소로 사용하고 localStorage는 데모·캐시 용도로만 사용합니다.
- 학부모 링크에는 쓰기 키가 포함되지 않습니다.
