# Young’s Physics v3.7.9 — 물리2 15회차 유도기·전반사

2026-11-07 작성. **로컬 준비본 / 운영 미배포**입니다.

## 기준과 변경 범위

정상 복구된 v3.7.8 전체 소스를 기준으로 합니다. 운영 GitHub 커밋, Apps Script `/exec` 배포, 운영 Google Sheets의 실시간 상태와 이전 복구패치·v3.7.8 실제 적용 여부는 확인하지 않았습니다. 현재 운영 저장소의 소스 ZIP과 사전검사 결과를 먼저 확인해야 합니다.

기존 `physics2-basic-r15`를 `coming-soon`에서 `ready`로 활성화합니다. 중복 시험 ID를 만들지 않습니다. 총 9문항·100점, 배점은 `[10,10,10,10,10,15,15,10,10]`입니다. 원문 재도전 9문항과 새로 작성한 동형 객관식 9문항을 연결합니다. 6번의 7+8점, 7번의 10+5점, 8번의 ‘이유가 없으면 0점’ 조건을 유지합니다. 원문에서 세부 배점이 정해지지 않은 문항의 루브릭 분할은 사이트용 제안이며 교사가 판단합니다. 그림 가산 2점은 100점에 자동 가산하지 않습니다.

원본 문제 PDF와 해설 PDF는 바이트 단위로 보존했습니다. 4·5번에 공통 회로를 함께 보여 주는 보조 이미지는 원문 픽셀만 발췌·배치한 것입니다. `pages`의 세 번째 이미지는 표시용 보조 자산이며 원본 PDF는 여전히 2쪽입니다.

다른 43개 시험 정의, 물리1 16회차 구형/개정판 분리, 총괄평가 성적표 바로보기 UI와 학생별 영구 링크 처리는 변경하지 않습니다. 물리2 전자기·파동 총괄평가의 연결 목록에는 이미 15회차 ID가 있으므로 총괄 정의도 그대로입니다. 최종 카탈로그는 4과정 / 44시험 / ready 26 / 262문항입니다.

## 해설 검수의 출처 구분

1~8번 제공 해설의 수치와 결론은 유지했습니다. 3·5·6번은 제공 해설이 따르는 초기 유도기 전류 0 및 이상적 소자 전제를 명시했습니다. 8번의 이유 미기재 0점 조건은 교사 수동 채점 시 적용합니다. 사이트가 서술형 이유를 자동 판독하는 기능을 추가한 것은 아닙니다.

9번 제공 해설의 `2/√3`은 굴절률의 **경계값**으로 보존합니다. 추가 검수 설명에서는 `n=2/√3`이면 입사각이 임계각과 같고, 임계각을 초과하는 전반사 조건은 `n>2/√3`이라고 구분합니다. 원문 그림의 경계면을 따라 나가는 광선은 임계조건의 굴절광선입니다. 원문 답을 자동 오답 처리하거나 기존 점수를 재채점하지 않습니다. 원문과 보충 설명을 구분한 검수 해설은 `site/assets/documents/physics2/r15-verified-solution.pdf`입니다.

## 적용 전 — 자동 동기화에 특히 주의

이 패치 파일을 받는 것만으로 운영 사이트는 바뀌지 않습니다. 아래 절차는 사용자가 실제 배포할 때만 실행합니다.

1. 운영 GitHub 최신 소스 ZIP과 마지막 정상 커밋을 확보합니다. 과거 v3.7.5 누락 복구 및 v3.7.8이 적용되지 않았다면 먼저 정상 기준을 맞춥니다. 이 v3.7.9 증분은 그 누락을 복구하지 않습니다.
2. **정적 파일 배포 및 로그인된 교사 화면 재접속보다 먼저** Google Sheets 사본을 백업합니다. 기존 `app.js`는 인증된 교사 화면 초기화 시 카탈로그 버전이 바뀌면 `autoSyncCatalog(false)`를 실행할 수 있습니다. 수동 ‘시험 설정 서버 동기화’를 누르기 전에도 동기화가 일어날 수 있습니다.
3. 백업 대상은 `Courses`, `Exams`, `Questions`, `QuestionOverrides`, `Students`, `Reports`, 반·병합 관련 시트입니다. `physics2-basic-r15`의 기존 서버 문항/정답 수정본/기록 유무를 확인합니다. 이미 다른 15회차 성적이 서버에 존재하면 이번 패치를 바로 적용하지 말고 시험 버전 분리를 먼저 검토합니다.
4. 제공한 읽기 전용 검사기로 운영 저장소 사본을 검사합니다. 아래 명령의 경로는 **운영 GitHub 소스 사본**이며, 로컬 작업본이나 패치 폴더를 대신 넣지 않습니다.

```text
python CHECK_PATCH_v3.7.9.py "운영_GitHub_소스.zip"
python CHECK_PATCH_v3.7.9.py "운영_GitHub_소스_폴더"
```

기준과 다른 파일이 나오면 덮어쓰기를 중단합니다. 이 검사는 파일만 읽으며 저장소·Google Sheets·서버를 변경하지 않습니다. 실제 배포 파일에는 runtime 설정이 주입될 수 있으므로 GitHub **소스 사본**을 기준으로 검사합니다.

## 적용 순서

1. 기준 일치·시트 선백업·15회차 충돌 점검 후, `YoungsPhysics_v3.7.9_patch_from_v3.7.8.zip`의 파일을 기존 상대 경로에 맞춰 추가/교체합니다. 파일 삭제는 없습니다. ZIP 파일 자체만 저장소에 올리는 것은 적용이 아닙니다.
2. `npm test`가 통과하는지 확인하고 사용자가 승인한 GitHub Pages 배포를 진행합니다. `pages.yml`, `runtime-config.js`, `share-config.js`는 패치에 없으며 변경하지 않습니다.
3. 교사 페이지를 열면 기존 자동 동기화가 작동할 수 있습니다. 기존 서버 `syncCatalog_`는 `Courses`, `Exams`, `Questions`를 교체하며, 정적 문항이 없는 준비중 시험의 기존 Questions 행은 보존합니다. 정적 문항이 생긴 15회차는 새 문항으로 동기화됩니다. `QuestionOverrides`는 별도로 남아 기본 정답을 가릴 수 있으므로 검토가 필요합니다. 자동 반영되지 않은 경우에만 백업/충돌 확인을 마친 상태에서 수동 동기화를 사용합니다.
4. 물리2 → 15회 복습 테스트의 활성 상태, 9개 입력란, 전부 `1`일 때 100점, 부분점수·공란 처리, 원문/해설 PDF와 4·5번 회로 그림을 확인합니다. 가상 학생 또는 복제 시트로 검사하고 실제 학생 성적을 시험 데이터로 바꾸지 않습니다.
5. 기존 학생 영구 링크, 물리1 16회차 신구 분석, 물리2 14회·심화 4회, 학부모 총괄평가 ‘성적표 바로 보기’, 원문/동형 재도전, Word/PDF를 확인합니다.

**Apps Script 코드 변경/재배포, Cloudflare Worker 변경/재배포는 필요하지 않습니다.**

`installYoungsPhysics()`, 학생 마이그레이션, PIN 재설정, `repairReportStorage()` 및 전체 데이터 초기화는 실행하지 않습니다.

## 되돌리기

로그인된 교사 화면을 닫고 마지막 정상 GitHub 커밋을 복원/revert한 뒤 Pages를 재배포합니다. 이전 카탈로그로도 자동 동기화가 실행될 수 있으므로 되돌리기 전후 서버 설정을 비교합니다. 동기화된 `Courses`/`Exams`/`Questions`는 백업과 비교해 필요한 설정만 복원합니다. 배포 후 신규 15회차 학생 성적이 저장되었다면 **Reports/Students를 삭제하거나 백업 전체로 덮어쓰지 않습니다.** 새 기록이 참조하는 15회차 문항도 보존한 상태에서 복구합니다. 기존 토큰·지문·StudentId 및 QuestionOverrides를 임의 재발급/초기화하지 않습니다. Apps Script와 Worker는 변경하지 않았으므로 해당 배포의 롤백은 필요하지 않습니다.
