# Young’s Physics v3.7.5 — 물리1 16회차 구형/개정판 분리

> **로컬 검증본 / 운영 미배포.** 별도의 명시적 배포 요청 없이 GitHub, Apps Script, Google Sheets, Cloudflare Worker에 반영하지 마세요.

## 왜 구형 16회차를 수정하지 않았나

이미 저장된 학생의 성적 기록은 `examId=physics1-basic-r16`을 가리킵니다. 기존 시험은 6문항/100점이며, 문항 JSON, 시험 PDF, 원문·동형 재도전, 분석 기준을 **기존 그대로** 보존했습니다. 반면 새로 업로드된 시험은 7문항/100점이므로 기존 ID의 문항을 덮어쓰면 과거 점수 및 오답 분석이 뒤바뀔 위험이 있습니다.

## 버전별 등록과 교사 입력

> 이 파일은 **3 m 수정 시험지**가 반영된 최종 v3.7.5이며, 이전에 생성된 4 m 조건의 v3.7.5 패치 ZIP을 대체합니다. v3.7.5는 운영 미배포이므로 v3.7.4를 기준으로 이 ZIP을 바로 적용해야 하며 두 ZIP을 연달아 적용할 필요는 없습니다.


- 이전 16회차(구형): `physics1-basic-r16` (6문항, [10,10,20,20,20,20]); **기존 성적의 수정만** 허용.
- 16회차(개정): `physics1-basic-r16-v2` (7문항, [10,10,20,10,20,10,20]); **새로 입력할 모든 16회차 성적**에 사용.
- 교사 일반 시험 선택 목록에서는 개정판만 노출. 교사가 이미 저장된 구형 성적의 **수정**을 누르면 구형을 임시로 표시하고, 수정 완료·취소·학생 변경·신규 학생·포털 성적 입력 선택 이후 개정판으로 전환.
- 새 시험의 원문 PDF와 원본 정답 PDF는 별도 보존. **정답 검수 PDF**는 `site/assets/documents/physics1/r16-v2-verified-solution.pdf`.
- 종합 누적 분석의 16회차 포함 범위는 두 ID를 인정하지만, **같은 학생이 양쪽 기록을 가진 경우 16회차를 한 번만 집계**(개정판 우선). 개별 학생 포털의 각 시험 성적표/오답은 모두 계속 표시.

## 검수 정오표

- 4번: 최종 수정 문제지의 가로등 위치는 사람 뒤 **3 m**이며, 제공 해답도 **2 m**로 일치합니다. 사람-거울 1 m, 가로등-거울 4 m이므로 최소 거울 세로 길이 = 10×1/(1+4)=**2 m**입니다. 구형 6문항 시험의 정답은 손대지 않았습니다.
- 겉보기 깊이(7번): 사람이 본 물고기 40 cm, 물고기가 본 사람 60 cm(수면에 거의 수직인 관찰 근사).

## 절대 수정하지 않은 항목

`apps-script/Code.gs`, `apps-script/appsscript.json`, `cloudflare-worker/index.mjs`, `.github/workflows/pages.yml`, `site/assets/runtime-config.js`, `site/assets/share-config.js`, 인증 설정, 학생 ID/토큰/지문 관련 핵심 코드. 시험의 원본 `physics1-basic-r16.json`, `r16.pdf`, `r16-p1.png` 및 기존 42개 시험 항목(단, 물리1 총괄의 회차 연결 목록 확장)은 불변입니다.

## 적용 전 필수 확인

1. 운영 GitHub 커밋과 운영 Apps Script `/exec`, 운영 Sheets 버전이 **이 로컬 정본 v3.7.4**와 실제로 같은지 비교합니다. 불일치 시 운영본과 패치를 병합해 다시 검증해야 합니다.
2. 운영 Sheets 원본 백업: `Students`, `Reports`, `Exams`, `Questions`, `QuestionOverrides`, 병합·링크 관련 시트. 특히 기존 16회차 성적 행에 지정된 `examId`와 토큰/지문을 감사용으로 사본 저장.
3. `QuestionOverrides`에 양쪽 `examId`별 수정본이 있는지 대조. 새 시험 정답을 덮어쓰거나 구형에 복사하지 않습니다.
4. **시험 설정 서버 동기화**는 `Exams`와 `Questions` 전체 교체 가능성을 수반하므로 백업·충돌 검사가 선행되어야 합니다. 운영 GitHub 변경만으로 Sheets 등록이 마무리된 것으로 가정하지 않습니다.
5. 검수 완료 후 명시적 요청에 따라 GitHub 소스 적용 → 정적 페이지 검증 → 교사 인증/학생 링크 확인 → Sheets 시험 설정 동기화(필요 시) → 신규/구형 각 1명 테스트(개인정보 없는 테스트 기록) 순서로 진행합니다.
6. 실운영에는 현재 변경이 반영되지 않았습니다. **이 ZIP은 배포를 수행하지 않습니다.**

## 롤백

GitHub 변경은 보관한 직전 커밋/소스 ZIP v3.7.4로 되돌립니다. 서버 동기화로 `Exams`/`Questions`를 변경했다면 **배포 전 백업으로 정확히 복원**합니다. 이미 신규 v2 성적이 생겼을 경우에는 해당 행을 삭제하거나 구형 ID로 바꾸지 말고, 관련 성적/링크 데이터 보존 방안을 확정한 뒤 롤백하세요. Apps Script·Worker는 이번 패치에 변경이 없어 재배포할 필요가 없습니다.
