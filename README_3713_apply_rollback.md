# Young’s Physics v3.7.13 — 학생 검색·반 배정·학교명 수정

이 문서는 v3.7.13용입니다. 운영 사이트를 자동 수정하는 프로그램은 포함하지 않았습니다.

## 어떤 파일을 사용하는가

- 정상 v3.7.12 적용 완료: `YP_3713_patch_from_3712.zip` 하나.
- 아직 정상 v3.7.10: `YP_3713_cumulative_from_3710.zip` 하나. v3.7.11 원본 최종, v3.7.12 전자기·파동 총괄평가, 이번 학생 관리 기능을 모두 포함합니다. 이전 패치들을 먼저/추가로 적용하지 않습니다.
- `YP_3713_full_source.zip`: 전체 보관·비교용입니다. 운영 설정을 백업하지 않은 상태에서 저장소를 지우고 대체하지 마세요.
- 기존 v3.7.5 누락 상태, 수정된 별도 소스, 재구성본 v3.7.11에는 위 패치를 임의로 적용하지 않습니다. 사전검사가 STOP이면 실제 저장소를 비교해야 합니다.

사용자는 v3.7.10까지 적용했다고 확인했지만 이후 v3.7.12 다운로드/적용 성공 여부는 확인되지 않았습니다. 버전 번호 표시만 보고 판단하지 말고 현재 저장소 전체 ZIP을 검사하세요.

## 적용 전에

1. 현재 GitHub 저장소 전체 ZIP과 정상 운영 커밋을 보관합니다. 운영 Apps Script의 실제 편집본/배포본이 이 프로젝트의 기존 API를 지원하는지 확인합니다. 실제 운영은 이번 작업에서 접근하지 않았습니다.
2. 운영 Google Sheets 사본을 백업합니다. 학생 검색은 읽기만 하지만 '반에 배정', '새 학생 생성', '학교명 저장'은 교사 권한으로 실제 데이터를 변경합니다. 이전 카탈로그 버전이 남아 있으면 교사 화면의 자동 동기화가 실행될 수 있습니다.
3. 패치를 임시 폴더에 풀고 다음을 실행합니다. Python은 이 사전검사에만 필요하고 웹사이트 사용에는 필요하지 않습니다.

```
python CHECK_3713.py "현재_GitHub_전체소스.zip"
```

`PASS_BASE`에서만 해당 패치를 적용합니다. `ALREADY_COMPLETE`이면 이미 반영되어 재적용할 필요가 없습니다. `STOP`이면 덮어쓰지 않습니다. 도구는 읽기 전용이며 파일/서버/시트를 바꾸지 않습니다.

## 실제 적용 순서

1. ZIP 파일 자체가 아니라 압축 안의 파일을 기존 저장소의 같은 경로에 추가/덮어씁니다. `.github/workflows/pages.yml`, `runtime-config.js`, `share-config.js`는 이번 패치에 없으며 운영값을 유지합니다.
2. 가능하면 로컬 또는 복제 소스에서 `npm test`를 실행합니다. 이번 목표 결과는 전체470 / 통과469 / 건너뜀1 / 실패0입니다. 건너뜀은 별도179명 학생 Excel 원본 부재입니다.
3. 평소 방식으로 정적 사이트를 배포합니다. Apps Script와 Worker의 코드/권한 변경·재배포는 없습니다. `installYoungsPhysics`, PIN 재설정, DB 초기화, 학생 링크 재발급, 수동 마이그레이션을 실행하지 않습니다.
4. 교사 페이지에서 Ctrl+F5로 새로고침합니다. v3.7.12에서의 증분은 카탈로그를 바꾸지 않으므로 이 기능 때문에 시험 설정 동기화를 강제로 실행할 필요가 없습니다. v3.7.10에서 누적 적용하는 경우에는 이전 안내대로 새 시험의 자동 동기화 결과를 확인하고, 충돌/정답 덮어쓰기 등을 먼저 확인합니다.
5. 복제 시트/가상 학생으로 이름 검색, 동명이인 선택, 반 배정, 학교 변경, 기존 학생 링크와 점수 보존을 확인한 후 운영 학생에 사용합니다.

## 사용법

반별 학생 영역의 '학생 이름 검색'에 이름 일부 또는 학교명을 입력합니다. 검색 범위는 현재 반/전체 학생입니다. 결과를 클릭하면 기존 성적 입력 화면으로 이동합니다. 검색은 학교와 이름을 다시 조합해 학생을 생성하지 않습니다.

'학생 검색·추가'에서 이름을 입력하면 기존 학생을 먼저 보여 줍니다. 기존 학생을 클릭하면 배정 확인 창으로 이동하고 '현재 반에 배정'을 눌러 추가합니다. '기존 학생 검색·배정' 버튼에서도 같은 작업을 할 수 있습니다. 학교·학년·반번호·학생 ID 끝6자리를 비교하여 동명이인을 구분합니다. 이미 등록된 학생은 선택할 수 없습니다. 다른 반 소속을 지우지 않고 새 반 소속만 추가합니다.

아예 새 학생은 '새 학생으로 생성'을 사용합니다. 같은 이름이 있으면 별도 학생이라는 확인을 받아 새 ID/영구 링크를 만듭니다. 기존 학생을 재등록하는 용도로 사용하지 않습니다.

선택된 학생의 '학교명 수정', 또는 학생 통합 링크 목록의 '학교명 수정'에서 변경합니다. 명시적인 StudentId와 school만 기존 서버 API에 보냅니다. 공란은 '미기입'입니다. 학교만 고치며 이름·학년·반번호·포털 토큰·지문·개별 성적 기록은 그대로입니다. 현재 프로필, 학부모 통합 포털 상단, 앞으로 입력하는 성적에 반영됩니다.

과거 성적표의 학교는 당시 값으로 보존됩니다. 과거 기록을 다시 수정·저장할 때 현재 프로필 학교와 다르면 현재 학교로 이 성적표도 저장할지 확인합니다. 취소하면 저장하지 않습니다. 확인해야만 그 성적표의 학교 표시도 바뀌며 점수/링크는 기존 수정 규칙을 따릅니다. 과거 학교명의 엑셀을 다시 일괄 업로드하면 별도의 자동 연결 규칙이 적용되므로, 전학/학교 수정 후 일괄 입력의 학교명도 확인하세요.

학교명 변경은 데모 저장소에서 정상 서버 저장처럼 가장하지 않고, 교사 서버에 연결해야 사용할 수 있게 했습니다.

## 되돌리기

- 적용 직전의 실제 운영 커밋으로 이번 정적 파일 변경만 되돌립니다. v3.7.5나 v3.7.7 전체를 덮어쓰지 않습니다.
- 정적 파일 되돌리기는 이미 저장한 반 배정/학교명 변경을 취소하지 않습니다. 잘못된 배정은 해당 학생만 반에서 제외하고, 잘못된 학교명은 해당 StudentId의 학교를 다시 수정합니다.
- 학생·성적·포털 토큰은 삭제/재발급하지 않습니다. 백업 이후 새 기록이 있을 수 있으므로 Sheets를 과거 사본으로 통째로 덮어쓰지 않습니다.
- 누적 패치 적용 이후 새 시험 성적이 생겼다면 v3.7.10으로 무조건 되돌리지 않습니다. 새 시험 정의·문항·자료는 유지한 채 이번 UI 변경만 되돌리는 방식으로 복구합니다.

## 검증 범위

실제 운영 E2E 검증은 아닙니다. 로컬 Node 회귀 테스트와 실제 GAS 함수를 사용한 메모리 Sheets 대체 검사, 실제 HTML/CSS/app/core를 Chromium에서 실행한 가상 학생 UI 검사를 수행했습니다. 환경에서 localhost HTTP 이동이 차단되어 브라우저 자산을 인라인으로 주입했고, API/localStorage는 메모리 대체를 사용했습니다. 운영 학생 데이터/비밀값은 사용하지 않았습니다.
