# Young's Physics v3.7.17 — 물리2 3회차 원본 8문항 복구

이번 수정은 일반 물리2 3회차 복습테스트에 별도의 개념정리 퀴즈 16개가 잘못 연결된 오류를 바로잡습니다. 실제 원본 `물리2-Quiz3회차.pdf`와 `물리2-Quiz3회차_해설.pdf`를 사용하며, 문제 번호는 1~8번입니다. 배점은 20·10·10·10·10·10·10·20점, 총 100점입니다. 1번의 네 소문항과 8번의 세 소문항은 각각 하나의 성적 입력 문항으로 유지합니다. 5번과 7번에는 해당 공통 지문과 그림을 함께 표시합니다.

원본 PDF와 그림을 다시 그리지 않았습니다. 기존 8문항 검수 해설의 2번 충돌 높이 3h/5, 8번 체공시간 A>B, 발사각·공기저항의 조건 설명을 그대로 유지합니다. 8번의 세부 배점은 문제지의 7·7·6점입니다.

`YP3717_R03_fix.zip`은 v3.7.15 및 두 종류의 v3.7.16 전체 소스를 기준으로 만든 수정 패치입니다. v3.7.16 중 8문항을 등록한 기존본과 개념정리를 16문항으로 잘못 등록한 본을 모두 지원합니다. 아직 v3.7.13만 적용한 경우에는 `YP3717_cumulative_from3713.zip`을 사용합니다. `YP3717_FULL_SOURCE.zip`은 전체 소스 보관·비교용입니다.

적용 전에 운영 저장소와 Google Spreadsheet를 백업합니다. 카탈로그 자동 동기화를 사용하므로 백업은 새 버전의 교사 화면을 열기 전에 마칩니다. 이번 파일 생성 과정에서 운영 서버에 접속하거나 실제 학생 데이터를 변경하지 않았습니다.

이번 패치에는 기존 16문항 성적을 보존하는 서버 처리가 포함됩니다. 먼저 운영 Apps Script의 `Code.gs`를 이 패치의 `apps-script/Code.gs` 내용으로 교체하고 저장합니다. 기존 웹 앱의 `배포 → 배포 관리 → 편집 → 새 버전 → 배포`로 갱신하여 같은 웹 앱 주소를 유지합니다. `appsscript.json`, Script Properties, Spreadsheet 연결, PIN, 학생 식별값과 영구 링크는 유지합니다. 설치 함수를 다시 실행하거나 학생 링크를 재발급할 필요는 없습니다.

이어서 패치 내부 파일을 기존 GitHub 저장소의 같은 상대 경로에 추가·덮어쓰고 기존 배포 절차로 반영합니다. `site` 폴더 안에 다시 `site` 폴더를 넣지 않습니다. 운영별 설정인 `site/assets/runtime-config.js`, `site/assets/share-config.js`, `.github/workflows/pages.yml`은 패치 대상에서 제외했습니다. 현재 저장소를 삭제한 뒤 전체 소스를 새로 올리는 방식으로 적용하지 않습니다.

적용 후 교사용 화면을 새로고침하고 시험 설정을 서버에 동기화합니다. 물리2 → 3회차 복습테스트에서 성적 입력 칸이 1~8번, 만점이 100점인지 확인합니다. 학생에게는 해당 원본 문제와 검수 해설이 연결됩니다. CSV 예시는 `sample-data/physics2-basic-r03-example.csv`이며 Q1~Q8만 사용합니다.

구형 서버가 연결되어 있으면 새 화면은 3회차를 안전하게 동기화하거나 저장할 수 없다고 안내합니다. 이 경우 Apps Script가 저장만 된 상태인지, 기존 웹 앱에 새 버전을 배포했는지 확인합니다. 서버 업데이트 확인 전에 8문항과 16문항 기록이 서로 덮어써지지 않도록 막는 동작입니다.

기존 16문항 입력 기록이 있으면 ‘3회차 개념정리 (기존 기록)’으로 읽습니다. 그 기록의 ExamId, StudentId, token, fingerprint와 원래 입력값을 일괄 변경하지 않습니다. 같은 학생의 새 8문항 성적을 저장해도 기존 16문항 기록을 덮어쓰지 않으며, 정상 8문항 성적과 통계를 분리합니다. 정상 복습테스트를 대상으로 하는 물리2 역학 총괄의 누적 분석에는 개념정리 기록을 포함하지 않습니다. 이미 저장된 정상 8문항 기록은 계속 같은 ID와 링크로 읽습니다.

서버에 16문항용 정답 수정본이 있으면 동기화 때 보관용 정의로 옮겨 보존하여 정상 8문항 정답에 섞이지 않게 합니다. 저장된 채점 배열과 입력 배열의 길이가 서로 모순된 기록은 자동으로 다른 배점으로 재계산하지 않고 확인이 필요한 상태로 보존합니다.

현재 소스가 제공 기준과 일치하는지 확인하려면 선택적으로 `python CHECK_3717.py <현재 전체 소스 ZIP 또는 폴더>`를 실행합니다. 읽기 전용 검사이며 파일이나 서버를 수정하지 않습니다. `PASS_BASE`는 안내된 패치를 적용할 수 있는 기준, `ALREADY_COMPLETE`는 동일 수정본이 적용된 상태, `STOP`은 기준 파일이 달라 비교가 필요한 상태를 뜻합니다. 이 검사를 실행하기 위해 운영 데이터를 옮길 필요는 없습니다.

복구할 때는 GitHub 정적 파일과 Apps Script를 함께 검토합니다. 새 8문항 기록과 기존 16문항 기록이 함께 저장된 뒤에는 이전 v3.7.16 서버 코드로 되돌리면 두 기록을 구분하지 못할 수 있습니다. 성적 기록을 삭제하거나 시험 ID를 수동 치환하지 않고, 이 버전의 기록 구분 처리를 유지한 상태에서 필요한 UI·문항 변경만 되돌립니다. 동기화 전 Spreadsheet 백업은 원래 상태를 대조하기 위한 자료로 보관합니다.

원본 확인, 문항별 이미지 검수, 기존 자료 보존 및 자동 테스트 결과는 `VALIDATION_3717.md`에 기록합니다. 운영 사이트 배포와 실제 학생 데이터에 대한 실행은 포함하지 않습니다.
